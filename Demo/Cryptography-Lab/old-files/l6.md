# Task 5: Digital Signatures

A digital signature does two things at once: it proves a message came from the holder of a specific private key (**authenticity**), and it proves the message wasn't altered after signing (**integrity**). This is the same underlying mechanism used to verify software packages and secure emails.

## Task 5.1: Sign the Message

1. Confirm you are in the `~/rsa-lab` directory.

   ```bash
   cd ~/rsa-lab
   ```

2. Create a digital signature for `message.txt` using your private key.

   ```bash
   openssl dgst -sha256 -sign private_key.pem -out signature.bin message.txt
   ```

3. Confirm the signature file was created.

   ```bash
   ls -la signature.bin
   ```

   > **Info:** Under the hood, this command hashes `message.txt` with SHA-256, then encrypts that hash with your private key. The result — `signature.bin` — is your signature.

## Task 5.2: Verify a Valid Signature

1. Verify the signature against the original message, using your public key.

   ```bash
   openssl dgst -sha256 -verify public_key.pem -signature signature.bin message.txt
   ```

2. Confirm the output reads:

   ```
   Verified OK
   ```

   > **Info:** Anyone with your public key can run this same command to confirm the message truly came from you and hasn't been changed — without ever needing your private key.

## Task 5.3: See What Happens When the Message Is Altered

1. Open `message.txt` and change a word, the same way you did in Task 4.

   ```bash
   nano message.txt
   ```

2. Save and exit (`Ctrl + O`, `Enter`, `Ctrl + X`).

3. Try to verify the signature again, using the same command as before.

   ```bash
   openssl dgst -sha256 -verify public_key.pem -signature signature.bin message.txt
   ```

4. Confirm the output now reads:

   ```
   Verification Failure
   ```

   > **Info:** The signature was created for the original message. Once the message changed, it no longer matches — proving that even a single altered character invalidates a signature.

## Task 5.4: Restore the Original Message

1. Open the file again and restore the exact original text.

   ```bash
   nano message.txt
   ```

   ```
   This message proves the CloudLabs RSA lab environment is ready.
   ```

2. Save and exit (`Ctrl + O`, `Enter`, `Ctrl + X`).

3. Verify the signature one final time to confirm it passes again.

   ```bash
   openssl dgst -sha256 -verify public_key.pem -signature signature.bin message.txt
   ```

4. Confirm the output reads `Verified OK`.

You have successfully created and verified a digital signature, and confirmed how signature verification fails when a message is tampered with. Proceed to the **Summary**.

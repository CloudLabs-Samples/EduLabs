# Task 4: Detect Message Tampering

Encryption keeps a message private, but it doesn't by itself prove the message wasn't altered. That's the job of a **cryptographic hash function** like SHA-256, which produces a unique fingerprint for a given piece of data. Change even one character, and the fingerprint changes completely.

Your lab environment already stored a hash of the original, untouched `message.txt` when it was set up, in a file called `.original_message.sha256`. In this task, you will tamper with the message and use that stored hash to detect the change.

## Task 4.1: View the Stored Original Hash

1. Confirm you are in the `~/rsa-lab` directory.

   ```bash
   cd ~/rsa-lab
   ```

2. View the stored hash of the original message.

   ```bash
   cat .original_message.sha256
   ```

3. Note the long string of characters displayed — this is the SHA-256 fingerprint of the message exactly as it was created during setup.

## Task 4.2: Confirm the Current File Still Matches

1. Calculate the current hash of `message.txt`.

   ```bash
   sha256sum message.txt | awk '{print $1}'
   ```

2. Compare it visually to the value you saw in Task 4.1. They should be **identical**, since you haven't changed the file yet.

## Task 4.3: Tamper With the Message

1. Open `message.txt` in a text editor.

   ```bash
   nano message.txt
   ```

2. Change any word in the sentence. For example, change "ready" to "compromised".

3. Save and exit the editor.

   > **Note:** In `nano`, press `Ctrl + O` then `Enter` to save, followed by `Ctrl + X` to exit.

4. View the file to confirm your change was saved.

   ```bash
   cat message.txt
   ```

## Task 4.4: Detect the Tampering

1. Calculate the hash of the modified file.

   ```bash
   sha256sum message.txt | awk '{print $1}'
   ```

2. Compare this value to the original hash stored in `.original_message.sha256` from Task 4.1.

3. Confirm the two values are now **different**.

   > **Info:** This is exactly how file-integrity checks work in the real world — software downloads, container images, and system files are often published alongside a hash. If the hash you calculate doesn't match the published one, the file has been altered or corrupted in transit.

## Task 4.5: Restore the Original Message

Later tasks assume the original message text, so restore it now.

1. Open the file again.

   ```bash
   nano message.txt
   ```

2. Change the text back to the original sentence exactly:

   ```
   This message proves the CloudLabs RSA lab environment is ready.
   ```

3. Save and exit (`Ctrl + O`, `Enter`, `Ctrl + X`).

4. Confirm the hash now matches the original again.

   ```bash
   sha256sum message.txt | awk '{print $1}'
   cat .original_message.sha256
   ```

5. Confirm both values are identical.

You have detected tampering using a cryptographic hash. Proceed to **Task 5**.
